Three ready-to-send HTML campaigns, built table-based and tested against the usual client breakages. Preview them, copy the HTML, paste into Brevo. Every claim in the copy is taken from technext.asia or the ACRA record — nothing invented.

Brand blue #3167CA · 600px · Outlook-safe (VML buttons) · plain-text alternates included · technext.asia

How to use this page

  • Preview each campaign on desktop and mobile widths in the panel on the right.
  • Copy HTML puts the whole file on your clipboard, ready for Brevo's Paste your code editor.
  • Copy plain text gives you the text alternate — paste it into Brevo's plain-text field. Skipping it costs you deliverability.
  • Images are hosted in this repo and load over HTTPS, so they survive being pasted anywhere.
Before any of these go out: the sending domain still has no SPF record, and technextasia.com sits at DMARC p=quarantine. Unauthenticated mail from a young domain lands in spam no matter how good the template is. Fix DNS first — see the checklist at the bottom of this page.

Sending one of these in Brevo

  1. Brevo → Campaigns → /campaigns/listing → Create a campaign → Email. (The /campaigns/list/email URL is broken in this account — it renders an error page.)
  2. Sender: TechNext <hello@technext.asia> — the only verified sender on the account.
  3. Subject + preheader: copy them from the campaign card above. Brevo calls the preheader "preview text".
  4. Design → Paste your code → clear the box → paste the HTML from Copy HTML. Click into the textarea before pasting; a paste that lands before the editor mounts silently does nothing.
  5. Switch to the plain-text tab and paste the matching .txt.
  6. Send a test to an address that is in Campaign settings → test list (/campaign-settings/test-list). Campaign recipients are not used for tests.
  7. Check the test in Gmail web, the Gmail app, and Outlook desktop if you have it. Those three cover most of what breaks.
  8. Only then pick the list and schedule.

Merge tags

A greeting with an empty fallback is worse than no greeting. Always set the default filter.

Link tracking

Every outbound link already carries utm_source=email, utm_medium=newsletter, a per-campaign utm_campaign and a utm_content that identifies which CTA was clicked — so GA4 separates the hero click from the footer click. Change utm_campaign whenever you reuse a template, or two sends will merge into one row in reporting.

Pre-send checklist

Blocker — authentication. The real sending domain is technextasia.com (no dot) and it has no SPF record while already sitting at DMARC p=quarantine; technext.asia is at p=none. Brevo's own dashboard flags the account as non-compliant with Gmail, Yahoo and Microsoft bulk-sender rules, and no domain has been added to Brevo at all. Publish SPF, add and authenticate the domain in Brevo, then send.
  • SPF published, DKIM signed by Brevo, DMARC has a rua address
  • Domain added and authenticated inside Brevo, not just the sender address
  • Recipients actually opted in. These templates are written for a warm list — for cold prospecting use the plain outreach copy instead, which is deliberately image-free
  • Unsubscribe link tested on a real send, not just previewed
  • Plain-text alternate pasted, not left auto-generated
  • Subject under ~45 characters so it does not truncate on a phone
  • Preheader written, and different from the subject
  • utm_campaign updated for this specific send
  • Every link clicked in the test email, including the logo and the social icons
  • Images-off check: the email still makes its argument with no images loaded
  • Send time set to office hours in Asia/Singapore, not UTC

What was deliberately left out

  • No hero photography. Layout carries the design instead. Fewer images means fewer broken-image boxes, a smaller email, and no spam-filter penalty from an image-heavy body.
  • No 11-image email signature. That block belongs on a one-to-one email, not a campaign — it is weight without persuasion.
  • No invented metrics. Every figure here (10+, 11+, 4, the client names, the partner badges) comes from technext.asia; the legal footer comes from the ACRA record. "ISO 27001 (in progress)" keeps its qualifier — dropping it would be a false claim.
  • No Odoo partner tier claim. The site says "Certified Odoo Partner" and the badge file says "Odoo Ready Partner". The flagship email uses the site's wording; confirm which tier is correct before this goes anywhere contractual.
